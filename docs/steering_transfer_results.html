SEAL · Reasoning Steering

One math vector, three domains: steering transfers to code and logic

A single steering vector extracted from the MATH training set (layer 20, coefficient α = −1.0) applied unchanged to math, code, and logic on DeepSeek-R1-Distill-Qwen-1.5B. Across every domain, steering raised accuracy while cutting reasoning tokens.

Result: steering improved accuracy and reduced tokens in all three domains — including LogiQA, a domain the original SEAL paper never tested. The math vector generalizes without any per-task re-extraction or re-tuning.
Math · GSM8K +8.9 pts 73.0% → 81.9%  ·  tokens −52%
Code · MBPP +6.0 pts 36.8% → 42.8%  ·  tokens −24%
Logic · LogiQA +4.0 pts 32.7% → 36.7%  ·  tokens −36%

How to read / caveats
  • Accuracy is exact-answer match for math, pass@1 for code, and multiple-choice accuracy for logic. Tokens are the average total generated tokens per problem (the SEAL efficiency metric).
  • Setup: same model, prompt, greedy decoding (temperature 0), 10k-token budget, and steering config (layer 20, α = −1.0) across all three. Only the eval dataset changes. GSM8K reproduces the paper's baseline (73.0% vs 74.1%).
  • LogiQA is a seeded random 300 of the full test set (baseline and steered use the identical 300, so the comparison is valid); math and code are full standard test sets.
  • Code and logic gains are smaller, so a portion could be noise — especially logic at n = 300 (+4 pts ≈ 12 questions).
  • All runtimes are measured wall-clock (from each run's example_prompt.txt at start to metrics.json at end) on a single RTX 4090. Steered runs use HF generate (batch size 8, except GSM at 4); baselines use vLLM.
Model: deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B · steering vector from MATH train (500 correct + 500 incorrect traces), layer 20, α = −1.0 · generated with visualize_all.py.
