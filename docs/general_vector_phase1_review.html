Common confusion

“APPS package — generation” ≠ “get APPS hidden.pt”. Generation builds CoT traces. Hidden extraction builds hidden.pt from those traces. Traces exist → generation optional. Hidden missing → extraction mandatory.

How MATH and code weave

One extractor (hidden_analysis.py). Two keyword sets. Same on-disk schema {step, check_index, switch_index}. Pooler concatenates all rows from both domains, then mean(check∪switch) − mean(other). It does not average S_math and apps_v_code.pt.

4 · Key code to review (snippets only)

Full files stay in the PR diff. Here are the only pieces that define Phase 1 behavior.

Driver — mandatory MATH + APPS extraction scripts/build_general_vector.sh
Same hidden_analysis.py twice: math keywords for MATH, code keywords for APPS. This is the mandatory path — not gen_apps_vllm.py. 
# MATH (mandatory)
python hidden_analysis.py ... --type incorrect --sample 500 \
  --keep_layers 20 --keywords math
python hidden_analysis.py ... --type correct   --sample 500 \
  --keep_layers 20 --keywords math

# APPS (mandatory) — SAME script, different keywords
python hidden_analysis.py ... --type incorrect --sample 500 \
  --keep_layers 20 --keywords code
python hidden_analysis.py ... --type correct   --sample 500 \
  --keep_layers 20 --keywords code
Driver — persist hidden.pt under data/ so they are not lost with results/
results/ is gitignored. After extraction the driver copies into tracked data/{MATH,APPS}/hidden_*/hidden.pt. Pooling reads those copies. After the GPU run: git add data/*/hidden_* and commit. 
store_hidden "$MATH_HIDDEN_C" "data/MATH/hidden_correct_0_500/hidden.pt"
store_hidden "$MATH_HIDDEN_I" "data/MATH/hidden_incorrect_0_500/hidden.pt"
store_hidden "$APPS_HIDDEN_C" "data/APPS/hidden_correct_0_500/hidden.pt"
store_hidden "$APPS_HIDDEN_I" "data/APPS/hidden_incorrect_0_500/hidden.pt"

python build_general_vector.py \
  --domain "math=${MATH_STORE_C},${MATH_STORE_I}" \
  --domain "apps=${APPS_STORE_C},${APPS_STORE_I}" \
  --layer 20 --out results/general/S_general_math_apps_phase1.pt
Pooler — SEAL contrast over both domains build_general_vector.py
Phase 1 default = pool ALL boundary vectors (no --balance). Formula matches upstream vector_generation.py. 
# per domain: split rows using check_index / switch_index
other = h[~isin(check ∪ switch)]

# Phase 1: concat every domain, then one contrast
S = mean(all check ∪ switch) − mean(all other)
# apply with coef -1.0
Keyword sets live in one file hidden_analysis.py · expand if needed
No second extractor for APPS. KEYWORD_SETS["math"] and ["code"] are both in SEAL’s hidden_analysis.py.
