Mathematical explanation

Will S_general be the same as S_combo?

They can be mathematically related, but they are not generally the same. The answer depends on how domains are balanced and whether domain vectors are normalized before they are combined.

Short answer: if both classes are balanced equally by domain, S_general is the average of the raw domain vectors. A normalized S_combo is generally different.

1Define each domain vector

For MATH and code, build one contrast vector per domain:

S_math = mean(RT_math) − mean(E_math)
S_code = mean(RT_code) − mean(E_code)

RT means reflection and transition boundary vectors. E means execution boundary vectors.

2If S_general balances both piles by domain

Suppose S_general uses equal MATH and code counts inside both the RT pile and the execution pile: 

S_general
= (mean(RT_math) + mean(RT_code)) / 2
  − (mean(E_math) + mean(E_code)) / 2

Rearrange the terms:

S_general
= 1/2 × (
    mean(RT_math) − mean(E_math)
    + mean(RT_code) − mean(E_code)
  )

= (S_math + S_code) / 2
Therefore: with class-stratified, equal-domain weighting, S_general is exactly the average of the raw domain vectors.

3Compare it with a raw S_combo

If the raw combination is defined as:

S_combo = S_math + S_code

then:

S_combo = 2 × S_general

They point in exactly the same direction. Only the magnitude differs. Multiplying a vector by 2 does not change its direction.

4But the planned S_combo uses normalization

If the combination is instead:

S_combo =
    normalize(S_math)
    + normalize(S_code)

then it is generally not the same as S_general.

For example, suppose:

||S_math|| = 100
||S_code|| = 10

Raw averaging keeps that magnitude difference:

S_general = (S_math + S_code) / 2

Unit normalization removes it:

S_combo =
    S_math / 100
    + S_code / 10
MATH has much more influence in the raw average because its vector is ten times larger. After normalization, MATH and code contribute equal unit length. This can change the vector’s direction, not only its magnitude.

5What about pooled S_general?

A pooled vector is calculated as:

S_general =
    mean(all RT boundary vectors)
    − mean(all execution boundary vectors)

If MATH and code contribute different numbers of boundary vectors, their weights inside those means are different: 

RT mean:
    domains weighted by their RT counts

Execution mean:
    domains weighted by their execution counts

A domain can therefore have one weight on the positive side and another weight on the negative side. In that case, the pooled vector cannot be rewritten as one simple average of S_math and S_code.

Summary

Unbalanced pooled S_general ≠ Raw or normalized S_combo, generally
Class-balanced S_general = Average of the raw domain vectors
Normalized S_combo ≠ S_general, generally, because normalization changes domain weights
Comparing S_general with normalized S_combo is a meaningful experiment. But if every class is perfectly domain-balanced and S_combo uses raw vectors, the two differ only by scale.
