SEAL vector geometry · Research note

Will S_general equal S_combo?

Sometimes they collapse to the same direction. Sometimes pooling and normalization make them genuinely different. The deciding factors are domain weights, class weights, and whether vectors are normalized before combination.

Short answer: an equal-domain, class-stratified S_general equals the average of raw domain vectors. A count-weighted pooled vector or a unit-normalized combo generally does not.

Definitions

Domain vectors

MATH and code separately

S_math = μ(RT_math) − μ(E_math) S_code = μ(RT_code) − μ(E_code)

RT combines reflection and transition boundaries. E is execution.

Normalized combo

Equal direction weight

S_combo = normalize(S_math) + normalize(S_code)

Normalization removes each vector’s original magnitude before addition.

Three constructions that look similar—but are not

A · Count-weighted pool

Phase 1 S_general

μ(all RT rows) − μ(all E rows)

Domains with more rows receive more weight. RT and execution can even use different domain weights.

B · Class-balanced pool

Strictly balanced S_general

equal RT/domain equal E/domain then subtract

Every domain contributes equally inside both conditional means.

C · Unit-normalized combo

S_combo

S_math / ||S_math|| + S_code / ||S_code||

Every domain direction contributes equal unit magnitude, regardless of raw vector strength.

The exact equality

If both classes contain the same amount from every domain:

S_general = ( μ(RT_math) + μ(RT_code) ) / 2 − ( μ(E_math) + μ(E_code) ) / 2 = ( [μ(RT_math) − μ(E_math)] + [μ(RT_code) − μ(E_code)] ) / 2 = (S_math + S_code) / 2
Therefore raw S_math + S_code is exactly 2 × S_general. They have the same direction and differ only in magnitude.

Why count-weighted pooling breaks the equality

The pooled means use class-specific row-count weights:

S_general = α_math_RT · μ(RT_math) + α_code_RT · μ(RT_code) − β_math_E · μ(E_math) − β_code_E · μ(E_code)

For this to equal one weighted combination of domain vectors, the weights must align:

α_math_RT = β_math_E α_code_RT = β_code_E
If MATH supplies 70% of execution rows but only 35% of RT rows, no single coefficient on S_math reproduces the pooled expression. The positive and negative sides weight MATH differently.

Why unit normalization changes direction

Take a simple two-dimensional example:

S_math = [10, 0] ||S_math|| = 10 S_code = [0, 1] ||S_code|| = 1 raw average = [5, 0.5] normalized combo = [1, 1]

The raw average points mostly toward MATH because its vector is ten times larger. The normalized combo gives both directions equal length.

What experiment remains meaningful?

Test shared activation geometry Compare count-weighted pooled S_general with normalized S_combo. Both weighting and normalization can change direction.
Test domain balancing Compare Phase 1 pooling against class-stratified pooling. This isolates whether unequal boundary counts drive the result.
Test normalization only Compare class-stratified S_general with normalized S_combo. Their difference comes from domain-vector magnitudes.
Avoid a redundant comparison Class-stratified S_general versus the unnormalized average of domain vectors is an identity, not an empirical hypothesis.
