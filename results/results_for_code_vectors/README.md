# Results for the code steering vector (S_code = vectors/apps_v_code.pt)

Runs produced by steering with the APPS-derived code vector, grouped here per the
convention in ../README.md (results grouped by the vector that produced them).

## Provenance

The MATH500, APPS, GSM, and MBPP runs below were **imported from the separate
`Andwwy/v_code-SEAL` repo**, not produced in this repo. They were generated by
that repo's eval harness, which predates this repo's LogiQA `</think>` grader
fix. That fix is LogiQA-only (it lives in logic_utils.extract_choice), so it does
not affect these four: MATH500/GSM are graded by the vendored Omni-MATH rule
grader and APPS/MBPP by executing the tests. Their predictions.jsonl are the raw
model generations and can be re-graded if needed.

Two naming notes from the import:

* In v_code-SEAL the GSM and MBPP runs were stored under a directory named
  `baseline_10000_vector_500_500_layer_20_transition_reflection_steervec` -- which
  is byte-for-byte the name this repo uses for the MATH vector. The source .pt was
  verified by md5 to be apps_v_code (the code vector), so the runs are genuine
  code-vector results; they have been renamed to `code_vector/vectors_apps_v_code/`
  here to remove the collision.
* All four now share the `code_vector/vectors_apps_v_code/` path, matching what
  `eval_steering_vector_benchmarks.sh VECTOR_NAME=code_vector` produces for the
  in-repo LogiQA run (vectors/apps_v_code.pt -> "vectors_apps_v_code").
